# Task 1.2a: Fit Report Hierarchy

## Decisions

Primary recommendation format: Option A, score-based recommendation

Rationale:
- The app already computes a deterministic fit score, so surfacing it first is both honest and fast.
- A score plus short recommendation answers "should I apply?" faster than forcing users to interpret several diagnostic panels.
- Score bands map cleanly to primary CTA states.

## What Shows First

- Job title and company context
- Overall match score
- One-sentence recommendation
- One primary action based on score
- `Show Details` and `Try Another Job` secondary actions

## What Hides Behind Details

- Overall sub-scores
- matched keyword view
- missing keyword view
- recommendation list
- supporting evidence rows

## Implementation Plan

- Keep the full report logic
- Move diagnostics behind `Show Details`
- Map score bands to primary actions:
  - `75+` → `Apply Now`
  - `60-74` → `Review Enhancement`
  - `<60` → `Skip This Role`
